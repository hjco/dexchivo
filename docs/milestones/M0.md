## Behavioral acceptance

1. Sending `ENABLE_LIVE_TRADING=true` to the API or `CHIVO_ENABLE_LIVE_TRADING=true` to Python
   prevents startup with an explicit error.
2. `GET /api/v1/system/info` reports `executionMode: PAPER`, `liveTradingEnabled: false` and the M0
   limitations.
3. OpenAPI contains no order route.
4. Numeric JSON financial values are rejected by contracts; decimal strings are required.
5. The shared signal fixture validates in both Vitest and Pytest.
6. The dashboard shows real API availability and does not display fabricated prices, balances or
   PnL.
7. Postgres and Redis become healthy under `docker compose up -d --wait`.

## Verification notes

- API LIVE rejection was exercised as a process smoke test:
  `ENABLE_LIVE_TRADING=true node apps/api/dist/server.js` exits non-zero with
  `ENABLE_LIVE_TRADING must be false`.
- Health, system metadata and dashboard checks were exercised against running processes on temporary
  ports to avoid colliding with developer services.
- The local verification environment used Node 26.12/pnpm 12.14, Python 3.13.17 via uv, Docker 29.9
  and Docker Compose v5.6.1. CI targets Node 22 and Python 3.13.

## Known limitations

- Contracts are source-only packages; a formal build is needed before external publishing.
- Readiness checks configuration only; database/Redis dependency checks belong to M1.
- Compose runs infrastructure only, not the applications.
- The Next.js dependency and build may emit upstream warnings; these are tracked as dependency
  updates, not M0 feature gaps.
